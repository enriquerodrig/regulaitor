## 1. Executive summary

v0.1.22.1 diagnostic identified **H1 (validator-too-strict vs eval-metric mismatch) as DOMINANT cause of v0.1.22 verdict_match drop (10/16 RHR cases = 62.5%)**. Production validator's Check 3 `text_normalized_match` (strict substring after normalization) rejects Sonnet's paraphrased/summarized citations even when (article + apartado) DO exist in corpus. Auditor's Tier 1 quorum then counts these false-negatives as "invalid" → escalates to RHR → verdict_match drops vs ARM B baseline.

v0.1.23 ships **Design B (Auditor-only intervention)**: inline helper `is_lenient_valid(audit) = audit.article_exists AND (audit.apartado_exists != False)` in `agents/auditor.py`. Tier 1 quorum counts `not is_lenient_valid` (Check 1+2 only). Finding-Lenient aggregation STILL uses `r.validated` (strict 3-check). Production validator (`citation/validator.py`) + `citation/schemas.py` BYTE-UNCHANGED.

Expected outcome (estimated, NOT measured pre-spec): ~6-7 of the 10 H1 cases flip RHR → PASS; verdict_match 0.30 → ~0.40-0.45 on H10 30-case cohort. Paid mini-validation confirms or refutes the prediction.

§6 invariant interpretive distinction (the centerpiece for ADR-0030): "no citation, no answer" is enforced at TWO layers — (a) per-citation validator (existence + text match) which remains BYTE-UNCHANGED + (b) Auditor aggregation (Finding-Lenient + Strict-Answer + Tier 1 quorum) which is the LEGITIMATE locus of interpretive policy. v0.1.23 refines the Tier 1 quorum interpretive policy ONLY. Validator-detected fabrications (article doesn't exist; apartado doesn't exist) still BLOCK the answer via Finding-Lenient path.

## 2. Context

### 2.1 Why now

v0.1.22.1 diagnostic surfaced a non-obvious layered-system inconsistency:
- v0.1.18 ADR-0024 introduced hierarchical containment match in EVAL metrics for citation scoring (purely measurement-side)
- v0.1.21 ADR-0027 introduced Tier 1 quorum in Auditor (production-side aggregation)
- Production validator stayed STRICT at H4 design (byte-unchanged across all milestones)
- The eval-metric hierarchical containment was NEVER propagated to production validator OR to Auditor's quorum-counting
- Tier 1 quorum reads STRICT validator output as ground-truth → escalates RHR on paraphrased-citation cases that eval-metric considers valid

v0.1.22 paid validation exposed the impact: verdict_match flat at 0.30 vs bar 0.35 + citation_precision/recall regressed. v0.1.22.1 diagnostic identified the mechanism. v0.1.23 ships the intervention.

### 2.2 Why Design B (not A or C)

User-validated brainstorm 2026-05-25:
- **Design B chosen** (Auditor-only; LOW §6 risk; `validator.py` + `schemas.py` BYTE-UNCHANGED)
- Design A rejected (validator.py direct change; HIGHER §6 risk; harder to argue byte-unchanged claim)
- Design C rejected (schema field addition; MEDIUM §6 risk; more invasive)

Design B achieves the same OUTCOME (verdict_match lift) with the LEAST §6 risk surface. ADR-0030 documents this trade-off honestly.

## 3. Architecture / Scope (7 decisions)

### D1 — Implementation: inline helper in auditor.py

```python
# src/regulaitor/agents/auditor.py (NEW inline helper; ~10 lines)
def _is_lenient_valid(result: AuditResult) -> bool:
    """v0.1.23 (ADR-0030): for Tier 1 quorum counting, a citation is 'valid
    enough' if its (article, apartado) tuple exists in corpus. Strict text
    match (Check 3) is preserved on the AuditResult.validated field for
    Finding-Lenient aggregation + confidence reporting + future use-cases.

    Mirrors the v0.1.18 ADR-0024 eval-metric hierarchical containment concept
    applied at the Auditor aggregation layer (NOT at validator layer; §6
    invariant byte-unchanged at validator). See ADR-0030 §6 interpretive
    distinction.
    """
    if not result.article_exists:
        return False
    # apartado_exists is None when citation has no apartado (article-level cite)
    if result.apartado_exists is False:
        return False
    return True
```
