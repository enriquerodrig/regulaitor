## 1. Context

The H13 Council of Judges (ADR-0014) shipped as an **advisory layer**: 3-judge panel records evidence per chat turn but NEVER mutates the deterministic Auditor verdict in H13. The H15 promotion seam (per `src/regulaitor/agents/council.py:33`) is the module constant `_COUNCIL_BINDING: bool = False` together with `MonotonicEscalatePolicy` (added in H13 T7, fully implemented + tested but wired-OFF). The H15 §16.3 deferral list explicitly carried this as post-H15.X work; v0.1.19 closes it.

**Empirical context (from H13 paid run, 21 chat cases with Council forced)**:

- Council DIVERGED from Auditor on **12/21 cases (57%)**.
- Of those 12 divergences:
  - **7/12 Auditor=RHR → Council=valid** (the panel is MORE leniente than the deterministic Auditor on ambiguous cases — the false-RHR pattern). NOT addressed by v0.1.19's conservative-only binding (per Q1 Option A choice).
  - **1/12 chat-11 Auditor=PASS → Council=RHR** (escalation case the Council was designed to detect). Addressed by v0.1.19's binding IF Council was unanimous BLOCK.
  - **4/12 other divergences** (BLOCK/RHR mixes). Mostly preserved by conservative-only semantics.

**The §6 invariant interpretive distinction (carried from ADR-0024 D5)**:

Two citation layers in RegulAItor:

- **Production-side citation VALIDATION** (`src/regulaitor/citation/validator.py`, the §6-invariant guardian): "Does the citation exist + literally match the corpus?" → byte-unchanged in v0.1.19.
- **Aggregation/escalation layer** (`auditor.py` Lenient-Finding+Strict-Answer + `council.py` advisory/binding): "Given per-citation validations, what's the turn-level verdict?" → v0.1.19 modifies ONLY the Council binding seam (flag flip + wiring); the Auditor aggregation itself stays byte-unchanged.

The "no citation, no answer" guarantee operates entirely on the first layer. v0.1.19 only changes what happens when the deterministic Auditor returns PASS AND the Council unanimously disagrees with BLOCK votes — promote to RHR (human review). NEVER relaxes BLOCK or RHR to PASS (that direction would weaken §6).

## 2. Decisions

### D1 — Conservative-only Council binding (no Auditor aggregation change)

Flip `_COUNCIL_BINDING: bool = True` in `src/regulaitor/agents/council.py`. Wire `MonotonicEscalatePolicy.would_escalate()` into orchestration via new `bind_verdict()` helper. The escalation rule is conservative-only:

- **PASS → RHR** when Council votes are 3/3 ok AND all 3 votes are BLOCK (unanimous BLOCK).
- **NEVER** relaxes BLOCK or RHR. The 7/12 H13 false-RHR pattern (Auditor=RHR → Council=valid) is NOT addressed by v0.1.19. Deferred to v0.1.20+ evidence-driven decision.
- **NEVER** escalates from a non-unanimous Council (2/3 BLOCK keeps PASS).

§6 invariant ROCK-SOLID: only adds conservatism; monotonic in the safe direction.

Rejected alternatives (per Q1 brainstorming):

- **Option B Bidirectional binding** (RHR → PASS on unanimous valid) — rejected. Would weaken §6 at the aggregation layer; deferred to v0.1.20+ evidence.
- **Option C Auditor aggregation change** (e.g. ≥2/3 Findings pass → PASS) — rejected. Affects EVERY chat case (not just Council-triggered); larger scope; speculative; awaits v0.1.20 measurement.

### D2 — Hardcode `_COUNCIL_BINDING=True` (production ship)

Flip the module constant; no env override. Production runs with binding ON for all chat traffic. Safe under monotonic-conservative semantics (only adds conservatism). v0.1.20 paid bundle measures real production behavior directly.

Rejected alternative (per Q2 brainstorming):

- **Env-overridable via `REGULAITOR_COUNCIL_BINDING`** — rejected as YAGNI. Mirrors ADR-0016 prompt-version seam pattern, but the conservative-only semantics make env-gated rollout unnecessary. Simpler test surface.

### D3 — `bind_verdict()` helper + `"COUNCIL_BIND:"` reason prefix

NEW top-level function in `src/regulaitor/agents/council.py`:

```python
def bind_verdict(
    audited: AuditedAnswer,
    review: CouncilReview,
    council: CouncilAgent,
) -> AuditedAnswer | None:
    """Apply Council binding to the audited verdict (v0.1.19 / ADR-0025).

    Returns a new AuditedAnswer with the escalated verdict + a
    "COUNCIL_BIND:"-prefixed reason iff:
    1. _COUNCIL_BINDING is True (module flag; True in v0.1.19+).
    2. The CouncilAgent's policy exposes a `would_escalate(audited_verdict,
       judges) -> AuditVerdict` method (MonotonicEscalatePolicy in v0.1.19).
    3. The policy's would_escalate returns a verdict that differs from the
       current audited.verdict.

    Returns None when no binding fires (the common case — Auditor
    verdict stands). The orchestration node uses None to mean "keep
    the existing audited_answer".

    Per ADR-0025 D1: the MonotonicEscalatePolicy is conservative-only
    (PASS → RHR on unanimous BLOCK; NEVER relaxes BLOCK or RHR), so this
    helper can never WEAKEN a verdict — only escalate.
    """
    if not _COUNCIL_BINDING:
        return None
    policy = council._policy  # private access INSIDE same module — clean
    would_escalate_fn = getattr(policy, "would_escalate", None)
    if would_escalate_fn is None:
        return None
    new_verdict = would_escalate_fn(audited.verdict, review.judges)
    if new_verdict == audited.verdict:
        return None
    # Binding fires. Build a new reason that preserves the original
    # auditor reason (if any) for audit-trail clarity.
    n_block = sum(1 for v in review.judges if v.ok and v.vote == AuditVerdict.BLOCK)
    n_ok = sum(1 for v in review.judges if v.ok)
    original_reason = audited.reason if audited.reason else "None"
    new_reason = (
        f"COUNCIL_BIND: {n_block}/{n_ok} judges voted BLOCK; "
        f"promoted {audited.verdict.value} -> {new_verdict.value}. "
        f"Original auditor reason: {original_reason}."
    )
    return AuditedAnswer(
        answer=audited.answer,
        verdict=new_verdict,
        audit_results=audited.audit_results,
        reason=new_reason,
    )
```

**Signature design notes (per Q5 brainstorming)**:

- Helper takes `council: CouncilAgent` (NOT the policy directly). Keeps the private-access concern (`council._policy`) **internal to `council.py`**. Orchestration's call site is fully public-API: `bind_verdict(audited, review, council_agent)`.
- `getattr(policy, "would_escalate", None)` keeps the helper polymorphic. Future policies without `would_escalate` (e.g. `AdvisoryMajorityPolicy`) cause `bind_verdict` to return None — no binding.
- `None` return when no binding: explicit sentinel; orchestration uses `if (new_audited := bind_verdict(...)) is not None:`.
- Reason format: parseable via `"COUNCIL_BIND:"` literal prefix. Preserves original Auditor reason for audit-trail clarity.

Rejected alternative (per Q3 brainstorming):

- **Reuse existing `_aggregate_reason` format with appended Council note** — rejected. Less distinguishable than D3's distinct prefix; format would need an exception for the PASS→RHR case (which has no per-citation invalid count). Cleaner to introduce a new prefix.

### D4 — `CouncilAgent.__init__` default changes to `MonotonicEscalatePolicy`

Per Q4 brainstorming. Single-line change in `src/regulaitor/agents/council.py:131`:

```python
# Before (v0.1.18):
self._policy: AggregationPolicy = policy or AdvisoryMajorityPolicy()

# After (v0.1.19):
self._policy: AggregationPolicy = policy or MonotonicEscalatePolicy()
```

`MonotonicEscalatePolicy.aggregate()` is IDENTICAL to `AdvisoryMajorityPolicy.aggregate()` (verified by existing test `test_monotonic_aggregate_matches_advisory` in `tests/unit/agents/test_council_policy.py`). The ONLY behavioral difference: `would_escalate()` becomes available, which `bind_verdict()` consumes.

`AdvisoryMajorityPolicy` is NOT deleted — it stays available for opt-in testing scenarios (e.g. `CouncilAgent(policy=AdvisoryMajorityPolicy())` for unit tests that want pure advisory behavior).

Rejected alternatives (per Q4 brainstorming):

- **Add would_escalate to AdvisoryMajorityPolicy** — rejected. Duplicates the would_escalate logic across two policy classes. Less clean than D4's separation.
- **Leave default unchanged; require explicit MonotonicEscalatePolicy construction** — rejected. Defeats the purpose of v0.1.19 (ships the seam but never fires in production).

### D5 — `_council_node` wiring + `_council_notice` update

Modify `src/regulaitor/orchestration/graph.py::_council_node` to consume `bind_verdict()`:

```python
def _council_node(state: ChatState) -> dict[str, Any]:
    """Council layer. Always records advisory review; in v0.1.19+ also
    binds verdict per MonotonicEscalatePolicy when council unanimously
    disagrees (PASS -> RHR only; conservative-only per ADR-0025).
    """
    try:
        council_agent = _council()
        review = council_agent.review(
            audited=state.audited_answer,
            context=state.context,
            trigger_reason=_council_trigger_reason(state),  # type: ignore[arg-type]
        )
        # v0.1.19: try to bind the verdict per MonotonicEscalatePolicy.
        # bind_verdict returns None when no binding fires (the common case).
        new_audited = bind_verdict(state.audited_answer, review, council_agent)
        if new_audited is not None:
            return {"council_review": review, "audited_answer": new_audited}
        return {"council_review": review}
    except Exception as e:
        logger.warning("council_node failed (swallowed): %s", type(e).__name__)
        return {}
```

`_council_notice` rendering (in `orchestration/graph.py` around line 200+) gets a new branch:

- **Binding fired**: when `state.audited_answer.reason` starts with `"COUNCIL_BIND:"`, emit `"Council unanimously disagreed with Auditor PASS. Verdict promoted to requires_human_review."` (or equivalent message in the user's language).
- **Advisory divergence** (current behavior, when binding did NOT fire): unchanged.

## 7. Consequences

**Positive:**

- **H13 ADR-0014 Council-binding seam closed**: the wired-OFF flag flipped + helper wired through. The H15 §16.3 deferral lineage on Council binding is resolved.
- **§6 invariant ROCK-SOLID**: monotonic-conservative escalation only. Validator layer byte-unchanged. Auditor aggregation layer byte-unchanged. Only the Council escalation seam (which was already a designed-in extension point) gets activated.
- **chat-11-style escalation cases caught**: Auditor=PASS + Council=3/3 BLOCK now promotes to RHR. The empirical case from H13 paid run is addressed (if Council was unanimous).
- **TFM defense narrative gains another clean layer separation**: validator (§6) vs Auditor aggregation vs Council escalation. Three distinct concerns; v0.1.19 touches only the third.
- **$0 milestone**: no paid LLM; clean test coverage; production-safe deployment.
- **Reusable `bind_verdict()` helper**: future policies (e.g. bidirectional, severity-weighted) can extend without modifying orchestration.

**Negative / accepted (per §22.22):**

- **H13's 7/12 Auditor=RHR → Council=valid pattern UNCHANGED**: the conservative-only direction doesn't address the false-RHR over-fire. Deferred to v0.1.20+ evidence.
- **Empirical effect on escalation rate UNMEASURED in v0.1.19**: $0 milestone; no paid run. v0.1.20 paid bundle measures real production behavior.
- **Pre-v0.1.19 reports stay frozen**: not $0-derivable from cache. Direct comparison with v0.1.20 numbers needs the "binding-on" caveat documented.
- **Council unanimity requirement is strict (3/3)**: a 2/3 BLOCK + 1 valid council does NOT escalate. If empirical data later shows 2/3 BLOCK is sufficient signal, a future milestone could loosen.
- **No partial-binding signal**: the `_council_notice` says "binding fired" or "advisory divergence"; doesn't distinguish "would have escalated but only 2/3 BLOCK so kept PASS". Minor cosmetic gap.
- **Cross-vendor judge dependency**: Council uses 3 different LLM vendors (Haiku/GPT-4o/Llama via router). If one vendor consistently degrades (e.g. Groq free-tier cap from H12/H13), the unanimity requirement may rarely be met. Acceptable risk under conservative-only semantics (failure mode is "no binding fires" — not a §6 violation).
