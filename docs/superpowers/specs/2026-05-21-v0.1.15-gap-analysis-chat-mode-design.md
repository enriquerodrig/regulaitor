## 1. Goal & honest framing

Ship a chat **gap-analysis surface** that mirrors the document-mode H5 use case via NL input: user says "tengo X, ¿qué me falta?" and gets a structured gap list grounded in corpus citations. Capability is shipped as **prompt-only extension** of the chat Analyst (v1.2 → v1.3) with **NL auto-detection** — zero API change, zero schema change, zero backend touch beyond the prompt file itself. Production default Analyst version stays v1.0 (byte-identical to current); v1.3 is opt-in via `REGULAITOR_ANALYST_PROMPT_VERSION=v1.3` for demos and the v0.1.20 paid A/B bundle.

**Honest TFM-defense framing**: v0.1.15 closes the TFM dual-target gap (LinkedIn publish + AI industry presencial session require a "what am I missing?" surface, not just Q&A). The capability ships; the empirical question "does v1.3 produce useful gaps without regressing Q&A?" is deferred to v0.1.20 paid bundle (same §22.22 pattern as H15/H15.1/v0.1.10/v0.1.11/v0.1.12 — capability shipped + measurement deferred to single bundled paid validation). The TFM demo is unlocked from v0.1.15 by setting one env var; the production-default flip waits for measurement.

**Single focus**: this milestone is solely the chat gap-analysis surface via prompt v1.3. Document-mode gap-analysis (H5 path) stays Q&A. The §17 thresholds + LLM-judge same-provider follow-up (v0.1.16), no-Answer-residual (v0.1.17), citation-granularity confound (v0.1.18), Auditor RHR + Council binding (v0.1.19), and single paid validation (v0.1.20) all remain DEFERIDO in the user-confirmed maximalist plan.

## 2. Decisions (D1–D6)

- **D1 — Scope = chat gap-analysis surface via prompt v1.3 only (single focus).** In scope: NEW `system.v1.3.md` prompt (extends v1.2 with Rule 8 detection + gap-output contract + 2 few-shots: precise + vague-real); +10 gold cases (5 `industry-g*` precise + 5 `industry-gv*` vague-real, all `corpus_esperado="auto"`); +2 unit test files ($0); ADR-0020; `docs/gap_analysis_chat_mode.md` memoria-ready WHAT/WHY/HOW/IMPACT. Out: API surface change (rejected — NL auto-detect chosen in brainstorming Q1); schema change (rejected — `Finding` reuse chosen in Q2); production-default flip (deferred to v0.1.20 per Q5); document-mode gap-analysis (out of milestone scope); paid LLM runs (deferred to v0.1.20 bundle).

- **D2 — Trigger = NL auto-detect inside prompt (no API surface change).** Rule 8 of v1.3 instructs the Analyst to detect gap-analysis pattern from the NL query when BOTH (a) a declaration of the user's state ("tengo X", "hemos implementado Y", "I have X", "we've implemented Y") AND (b) a gap-seeking question ("¿qué me falta?", "¿estoy cumpliendo?", "what's missing?", "am I compliant?") are present. When only one is present OR the query is a pure information request, regular Q&A mode applies. **Ambiguous → Q&A (safer default)**. Zero API change: `AskRequest` unchanged (still `{query, corpus, language, council}`); no `mode` parameter; no `/gap-analysis` endpoint. Production UX: vague users (mirroring `industry-v*` cases from v0.1.13) don't need to know the mode exists.

- **D3 — Output shape = reuse existing `Finding` (zero schema change, §6 trivially preserved).** Each gap = one `Finding` whose `text` describes what's missing + `citations` (≥1) point to the article that requires the obligation + `severity` per the gap-analysis severity scale defined in D4. Top-level `Answer.text` paraphrases the user's declared state (1-2 sentences, NO citation because INPUT not claim) + analysis intro. The `Answer.findings` carry all normative content. If declared state covers all retrieved obligations: ONE positive Finding "El estado declarado cubre las obligaciones aplicables del [artículo]" + citation + severity "info". Backend schemas (`Answer`, `Finding`, `Citation`, `AuditedAnswer`, `CitationDTO`, `FindingDTO`, etc.) **BYTE-UNCHANGED**. Auditor + citation-validator **BYTE-UNCHANGED**. Streamlit renderer **BYTE-UNCHANGED** (same Finding rendering).

- **D4 — Prompt v1.3 = v1.2 + Rule 8 + gap-output contract + 2 few-shots (Q&A example preserved verbatim).** Hard rules 1-7 from v1.2 BYTE-IDENTICAL. New Hard rule 8 = detection rules. New "Output contract — gap-analysis branch" subsection = output rules per D3. New severity scale for gap-analysis findings: `high` = blocks hard obligation, `medium` = documentation/process gap, `low` = procedural detail, `info` = positive coverage. Example 1 (Q&A "¿Qué dice el AI Act sobre sistemas de alto riesgo?") **byte-identical to v1.2** (regression-zero anchor on regular Q&A path). NEW Example 2 = precise gap-analysis (user names AI Act art 6 + declares EIA + supervisión humana → 3 gap Findings: logging art 12 / risk mgmt art 9 / QMS art 17). NEW Example 3 = vague-real gap-analysis (user says "creo que tenemos IA alto riesgo, tenemos control humano, ¿qué nos toca?" → gaps for clearly missing obligations + acknowledges ambiguity in `text`). Few-shot tokens added: ~250-400 to system prompt = ~$0.001 incremental per /ask call at Sonnet pricing (negligible).

- **D5 — Production default = v1.0 (byte-identical to current); v1.3 opt-in via env (matches boundary contract).** `REGULAITOR_ANALYST_PROMPT_VERSION` env seam from ADR-0016 reused unchanged. Env unset → v1.0 → production behavior byte-identical to v0.1.14. Env `=v1.3` → v1.3 active → gap-analysis detection + output shape available. v1.1, v1.2 remain on disk and selectable via env. For TFM demo (LinkedIn / industry session): one-line .env config unlocks the capability without flipping the default. **Backward-compat by construction: regression-zero on existing 54 chat cases when env unset; v1.3 also preserves the Q&A example so even when env=v1.3 the regular Q&A path stays functional.**

**Data flow (production, env unset → v1.0 loaded)**: identical to v0.1.14. Caller → `/ask` → `AnalystAgent.__init__(prompt_role="analyst", prompt_version=None)` → reads `REGULAITOR_ANALYST_PROMPT_VERSION` env (unset) → defaults `prompt_version="v1.0"` → loads `system.v1.0.md` → regular Q&A behavior byte-identical.

**Data flow (demo / eval, env set to `v1.3`)**: identical retrieval/Analyst plumbing; only the prompt content differs. Caller → `/ask` → `AnalystAgent.__init__(prompt_version=None)` → reads env=`v1.3` → loads `system.v1.3.md` → Analyst sees query + retrieved chunks + v1.3 instructions → applies Rule 8 detection → if gap pattern: emits Findings shaped as gaps with severity per scale; if Q&A pattern: emits Findings shaped as Q&A (Example 1 path); if ambiguous: defaults to Q&A. Auditor downstream validates every citation per its existing rules.

**Invariant**: §6 Auditor + citation-validator BYTE-UNCHANGED under any env state. The gap-analysis output uses the same `Finding{text, citations[], severity}` shape that Q&A uses, so Auditor's per-citation validation logic applies identically. A gap-analysis Finding with a hallucinated article would be rejected just like a Q&A Finding with a hallucinated article. The §6 "no citation, no answer" guarantee is preserved by construction — gap-analysis is a different prompt instruction set producing the same output schema, validated by the same downstream layer.

## 4. NL detection design (Rule 8 specifics)

**Trigger pattern** (both conditions must be present):

(a) **Declaration of user's state**:
- Spanish: "tengo", "tenemos", "hemos implementado", "ya hemos", "contamos con", "disponemos de", "actualmente usamos", "tenemos en producción", "tenemos en operación"
- English: "I have", "we have", "we've implemented", "we currently use", "we operate", "we maintain"

(b) **Gap-seeking question**:
- Spanish: "¿qué me falta?", "¿qué nos falta?", "¿qué me toca cumplir?", "¿qué nos toca?", "¿estoy cumpliendo?", "¿estamos cumpliendo?", "¿qué más necesito?", "¿qué más necesitamos?", "¿hay algo que se nos escape?"
- English: "what's missing?", "what do I need to add?", "what else do we need?", "am I compliant?", "are we compliant?", "is there anything we're missing?"

**Ambiguity → Q&A (safer default)**. Examples of ambiguous queries that go to Q&A:
- "Estoy en alto riesgo." (declaration without gap question)
- "¿Qué controles necesito para alto riesgo?" (gap question without declaration; pure information request)
- "Tenemos evaluación de impacto." (declaration without gap question)
- "¿Qué dice el AI Act sobre logging?" (pure information request)

**Cross-corpus gap-analysis**: when user's declaration spans multiple normative regimes (e.g. "tenemos IA en banca, ¿qué nos falta entre AI Act y NIS2?"), the Analyst uses the auto-corpus retrieval path (existing behavior; v0.1.13 industry-c cases already exercise this) and emits Findings per relevant norma. Each Finding cites the appropriate norma's article.

**Edge cases handled by Rule 8 + existing Hard rules**:

| Edge case | Handling |
|---|---|
| User declares ALL retrieved obligations met | ONE positive Finding `text="El estado declarado cubre las obligaciones aplicables del [artículo]"` + citation + severity `info`. |
| User declares an article that's NOT in retrieved chunks | Analyst does NOT cite it (Hard rule 4: no hallucinated articles). Auditor would reject the fake citation anyway (§6 invariant). |
| User declares an article that IS in retrieved chunks | Analyst MAY cite it as part of a Finding's reasoning but does NOT emit a gap for it (user already covers it). |
| Gap-question without any declaration | Treated as Q&A (pure information request). |
| Declaration without gap-question | Treated as Q&A on whatever the rest of the query is asking. |
| Both present but contradictory (e.g. "tengo X but not X, ¿qué me falta?") | Default to Q&A; Analyst's `text` should flag the contradiction. |
| Vague declaration with gap question ("creo que tengo IA alto riesgo, tenemos control humano, ¿qué nos toca?") | Rule 8 trigger fires (both (a) "tengo"/"tenemos" + (b) "¿qué nos toca?" present); vague handling means: emit gaps only for obligations clearly missing from the declaration; in `text` acknowledge ambiguity and recommend verifying the scope of declared controls. |
