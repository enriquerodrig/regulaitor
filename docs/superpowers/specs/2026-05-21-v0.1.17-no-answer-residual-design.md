## 1. Goal & honest framing

Ship a **$0 enhanced diagnostic** that disambiguates the no-Answer residual into 4 sub-cases (`refusal` / `analyst_raise` / `transport_error` / `other`) by mining the existing judge cache (which contains the full Analyst `actual_answer` text per cached judge prompt). The contribution is the **classified data + taxonomy + conditional intervention recommendation**, NOT the intervention itself. The intervention (Analyst prompt v1.4 OR harness retry-hook OR refusal-phrase seed expansion OR "no fix because Case A dominates") is decided by the user at v0.1.17 closure based on what the diagnostic reveals, and ships as a separate follow-up microhito if warranted.

**Honest TFM-defense framing**: v0.1.17 is the **diagnostic milestone**, not the fix milestone. The ~23% no_answer residual (H10 baseline `0cc9534`) and 2/14 H15 v1.2 holdout residual (dora-001, dora-004) are documented per `docs/auditor_calibration.md` but the existing `scripts/diagnose_baseline.py` classifier only labels `no_answer` coarsely (Analyst emitted no citations). It does NOT distinguish "Analyst correctly emitted structured refusal `findings=[]`" (Case A — system working as designed) from "Analyst raised RuntimeError after retry" (Case B — Analyst-side failure) from "transport error caught by harness sentinel" (Case C — operational). The intervention shape depends entirely on which dominates. Fix-first without diagnostic = fix-the-wrong-thing risk. v0.1.17 closes that gap.

**Single focus**: this milestone is solely the diagnostic. No Analyst prompt change. No harness change. No retry-hook. No paid LLM run. The contribution IS the classified evidence + the recommended-intervention table conditional on the actual class distribution.

## 2. Decisions (D1–D5)

- **D1 — Approach = diagnostic-first (intervention deferred).** v0.1.17 ships the diagnostic; the intervention (if any) becomes a clearly-scoped follow-up microhito (v0.1.17.1 if Case B/C dominates → prompt v1.4 or harness retry-hook; v0.1.18 absorbs the carry if Case A dominates → no fix warranted, the residual is upstream retrieval). Rejected: fix-first (shipping a speculative intervention without empirical diagnosis risks fix-the-wrong-thing); diagnostic + speculative intervention in single milestone (combines the disciplines but if Case A dominates the speculative fix is wasted scope).

- **D2 — Data sources = 3 canonical reports + 381-file judge cache.** Mine `evals/reports/latest.md` (H10 frozen @ `0cc9534`, 30 chat baseline, v1.0 prompt, ~7 no_answer cases per `scripts/diagnose_baseline` headline), `evals/reports/h15/candidate-v1.2.md` (H15 v1.2 30-case A/B, same gold set), and `evals/reports/h15/holdout-v1.2-chat.md` (H15 v1.2 14-case cross-corpus holdout, 2 residual per `docs/auditor_calibration.md:541`). For each `no_answer` case in those reports, scan `evals/cache/*.json` for matching judge prompts containing the case's `query` field — the cached `request.user` JSON body has `{query, actual_answer, expected_answer, cited_articles, expected_articles, criteria}`, so we extract the Analyst's full Answer text and classify by content. Cache-mining is heuristic (assumes the gold `entrada` appears exactly in the judge prompt's `query` field); query-mismatches yield "no cache entry" → classify as `analyst_raise` with documented ambiguity.

- **D3 — Taxonomy = 4-bucket classifier (refusal / analyst_raise / transport_error / other).** Algorithm:
  1. Locate cache entry by exact-match on `request.user.query == gold_case.entrada`. Use first matching entry (cache may have multiple entries per case, one per criterion eval).
  2. If NO cache entry matched → return `analyst_raise` (most likely: Analyst raised before judge was called; no actual_answer ever cached). Document ambiguity (could also be `transport_error` indistinguishable from cache absence; flagged in diagnosis report).
  3. If cache entry found, inspect `actual_answer`:
     - Empty string OR `"(backend error)"` sentinel → `transport_error` (harness sentinel for backend exception).
     - Contains any phrase from `REFUSAL_PHRASES` seed list (case-insensitive substring) → `refusal` (legitimate structured refusal per v1.1/v1.2/v1.3 Output contract).
     - Non-empty + no refusal phrase → `other` (Analyst-emitted prose without standard refusal phrasing; needs manual review; documented in diagnosis report).
  Seed list `REFUSAL_PHRASES`: 16 Spanish phrases + 6 English phrases (see §3 Architecture for the literal list). The seed is **non-exhaustive** by design; false negatives classified as `other` flag follow-up "expand seed list" sub-recommendation.

- **D4 — Output = per-case classification table + aggregate counts + conditional intervention recommendation.** `docs/no_answer_residual_diagnosis.md` (~150-220 lines) contains: dataset header (3 reports + commit SHAs + classifier version); per-report breakdown (H10 + H15 v1.2 + H15 holdout counts per class); per-case table (all no_answer cases, one row each: report / case_id / classification / actual_answer snippet first 200 chars / matched_phrase / confidence); trajectory analysis (H10 v1.0 → H15 v1.2 class-distribution shift = evidence of Intervention B effectiveness); recommended intervention (5 conditional branches: refusal-dominant → no v0.1.17.1 fix → carry to retriever/gold-review; analyst_raise-dominant → v0.1.17.1 prompt v1.4 + harness retry-on-RuntimeError; transport_error-dominant → v0.1.17.1 harness retry-on-transport hook; mixed → dominant class intervention + document carry-forward; other-dominant → v0.1.17.1 expand REFUSAL_PHRASES + re-run); §22.22 honest caveats (cache-mining heuristic; seed list non-exhaustive; 3 reports are canonical evidence — cases not in these reports out of scope).

- **D5 — Done-when (§22.22 honest, diagnostic-shipped pattern).** Code: `scripts/diagnose_no_answer.py` shipped + 6-8 unit tests green; classifier produces per-case labels on real data when invoked against the 3 reports + `evals/cache/`. Output: `docs/no_answer_residual_diagnosis.md` populated by the actual script run (NOT a hand-written placeholder); per-case table has real entries; recommended-intervention section computed from actual class counts. Full gate green: `uv run pytest -m "not slow"` ≥90% coverage + `uv run mypy src` strict 71 files exit 0 + redteam-smoke ≥0.92 (= v0.1.14/v0.1.15/v0.1.16 frozen carry). NO paid LLM run. Outcome: classified evidence shipped + intervention recommendation computed — both defend honestly (§22.22 pattern carried). Closure: ADR-0022; `docs/no_answer_residual_diagnosis.md` memoria-ready; decisions §v0.1.17 expansion; CLAUDE.md §16.3 (v0.1.17 marked done) + §27 (Hitos cerrados new bullet + Hito siguiente decided AT closure based on diagnostic verdict — v0.1.17.1 intervention OR v0.1.18 citation granularity if Case A dominates); evidence_matrix v0.1.17 row + ADR-count gate 21→22 + decisions-log line count refresh; memory roll-forward `v0.1.16_closed_v0.1.17_starting.md` → `v0.1.17_closed_<next>_starting.md` (where `<next>` is decided at closure); squash-merge to main + annotated tag `v0.1.17-no-answer-diagnosis` + post-merge `<squash-sha>` populate of 5 placeholders: (i) ADR-0022 Status line, (ii) decisions_log §v0.1.17 header line, (iii) evidence_matrix v0.1.17 tag-table row, (iv) CLAUDE.md §16.3 H15.X bullet v0.1.17 entry, (v) CLAUDE.md §27 Hitos cerrados v0.1.17 bullet.

**Data flow** (controller-driven, no runtime change to production):
1. Author writes `scripts/diagnose_no_answer.py` per recipe (T2 implementer).
2. Controller runs `uv run python -m scripts.diagnose_no_answer` against committed reports + populated cache.
3. Script outputs aggregate counts to stdout + writes `docs/no_answer_residual_diagnosis.md` with per-case table + recommended-intervention computed from actual counts.
4. T-pre-closure verification: controller inspects the generated `docs/no_answer_residual_diagnosis.md`; if data is reasonable (per-case table populated, recommendation section non-degenerate), proceed to closure. If empty/crashed, STOP and fix before closure.
5. Closure docs reference the data verdict.

**Invariant**: §6 Auditor + citation-validator + Pydantic schemas + DTOs + backend H1-H5/H7 + eval-internals + Analyst prompts v1.0-v1.3 + gold set ALL BYTE-UNCHANGED. The change is ONLY a new file under `scripts/` + 1 new test file + 2 new docs + closure docs.

- **Modifying `scripts/diagnose_baseline.py`** — existing baseline classifier stays unchanged; new diagnostic is a separate script that extends, not modifies, the existing one. Backward-compat preserved.
- **Backend changes** (Analyst code, retrieval, etc.) — entire `src/` untouched per ADR-0010 D8 carry; v0.1.17 is eval-side only.
