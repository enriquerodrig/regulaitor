## 2. Context

v0.1.22 ARM v0.1.22-prod 16 RHR cases (chat-001..030 subset). Per T5 mechanism diagnostic:
- 11/16 RHRs are Bucket C (NEW Tier 1 quorum: ≥2 invalid citations, ≥1 finding emitted, verdict=RHR)
- ~5/16 RHRs are Bucket E within-RHR (no clear quorum trigger; could be other escalation paths)

verdict_match drop hypothesis space (4 candidates):

### H1 — Validator-too-strict vs eval-metric mismatch

Production `src/regulaitor/citation/validator.py` uses H4 STRICT match (byte-unchanged across all milestones per §6 invariant). v0.1.18 ADR-0024 introduced hierarchical containment match in `evals/metrics.py` (eval-side only). If validator marks citations invalid that eval-metric considers valid, Tier 1 quorum (≥2 invalid → RHR) fires on cases the eval would score as cite-correct.

Signal: per-citation_audits show validator marking as invalid citations that match (apartado-of-article or article-prefix containment with) gold expected_citations.

### H2 — Gold expected_verdict misaligned with v1.5 refusal-as-Finding

H15 C1 pattern already documented: v1.5 emits structured refusal as Finding (1 Finding + corpus citation + severity=high). For cases where gold expects literal `block` but v1.5 returns `pass` with refusal-Finding content (Auditor's Lenient-Finding policy validates the citation → routes to PASS).

Signal: cases where gold expected_verdict=`block` AND actual_verdict=`pass` (or `requires_human_review`) AND emitted Finding has refusal-language pattern + corpus-grounded citation.

### H3 — Tier 1 threshold too aggressive (≥2 invalid)

Could be edge cases where Sonnet emits "extra" citations beyond gold (reinforcement citations) but gold-expected citations ARE present + valid. Extra citations may be invalid (Sonnet over-cited) but the answer IS supported.

Signal: per-citation_audits show K≥2 invalid + the gold expected citations among the valid subset.

### H4 — Sonnet legitimately citing wrong articles

Real Tier 1 catch (working as designed). Sonnet misunderstood query → retrieved wrong articles → answer is unsupported → Tier 1 correctly escalates to RHR.

Signal: per-citation_audits show all/most citations invalid + emitted citations have NO overlap with gold-expected.

## 3. Architecture / Scope

### D1 — Methodology

For each of 16 RHR cases in v0.1.22-prod chat-001..030:

1. Load case data: emitted_citations, expected_citations (gold), per_citation_audits trail, actual_verdict, severity, judge criteria_scores.
2. Compute per-hypothesis match:
   - **H1**: count citations where `validated=False` BUT `(emitted.articulo, emitted.apartado)` matches `(gold.articulo, gold.apartado)` per hierarchical containment rule (article-prefix or apartado-of-article). If ≥1 such citation exists, flag as H1-candidate.
   - **H2**: case where `gold.expected_verdict in {"block"}` AND `actual_verdict in {"pass", "requires_human_review"}` AND `len(findings) >= 1` AND ANY finding has refusal-language pattern (heuristic: `re.search(r"(no puede ser atendida|no es posible|fuera del ámbito|rechazo|reject|cannot be answered)", text, re.IGNORECASE)`). Flag as H2-candidate.
   - **H3**: case where `n_invalid_citations >= 2` AND `len(intersection(emitted_articles, gold_articles)) >= 1` AND `intersection_valid_subset` is non-empty. Flag as H3-candidate.
   - **H4**: case where `n_invalid_citations >= 2` AND `len(intersection(emitted_articles, gold_articles)) == 0`. Flag as H4-candidate.
3. Per case assign DOMINANT hypothesis (if multiple flag, take precedence: H4 > H1 > H3 > H2).
4. Report counts per hypothesis + per-case detail table.

### D2 — Decision tree for v0.1.23+ (explicit)

Based on hypothesis-attribution counts:

| Dominant hypothesis | v0.1.23 path | Risk level |
|---|---|---|
| H1 ≥ 50% (validator-too-strict) | Propagate hierarchical containment match from eval-metric to production validator. §6-adjacent change (validator IS the §6 enforcement layer). NEW ADR. Careful TDD. | HIGH (§6 risk) |
| H2 ≥ 50% (gold-misalign) | Update gold expected_verdict to accept `{block, RHR, pass-with-refusal-Finding}` for affected cases. NO src/ touch. Document gold semantic change. | LOW |
| H3 ≥ 50% (threshold too aggressive) | Tune Tier 1 quorum threshold ≥2 → ≥3 in `agents/auditor.py`. NEW ADR. Auditor src/ touch (§6 BYTE-UNCHANGED stays — Auditor changed at v0.1.21 already). | MEDIUM |
| H4 ≥ 50% (legitimate catch) | NO intervention. v1.5 prompt iteration OR retrieval tuning at v0.1.23+. Document Tier 1 working as designed; verdict_match drop is real cost of safety. | LOW (no change) |
| Mixed (no dominant) | 1+ surgical milestones per hypothesis. May need v0.1.23 + v0.1.24+. | VARIES |
