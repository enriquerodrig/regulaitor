## 3. Scope (3 items)

### D1 — Fix `scripts/v0120_compare.py` transition matrix bug

The current bug: when building the 3×3 transition matrix (v1.0 verdict → v1.4 verdict counts), the code populates only diagonal entries leaving off-diagonal at 0. The actual transitions (RHR→pass, pass→RHR, etc.) are not counted.

**Fix**: rewrite the transition counting block to iterate (case_id, arm_a_verdict, arm_b_verdict) tuples + increment counts at the correct cell. Add 1 unit test that constructs synthetic checkpoints with known transitions + asserts the matrix matches expected.

**Rename strategy**: keep `scripts/v0120_compare.py` name (the script logic generalizes to any v0.1.20+ comparison). Optional: add a thin wrapper `scripts/v0121_compare.py` that calls it with v0.1.21 vs v0.1.20 baseline paths. NOT in v0.1.21.1 scope; v0.1.22 plan can author the wrapper.

### D2 — Per-citation AuditResult persistence (Rich format)

**Schema change** in `evals/schemas.py`:

```python
class ChatCaseResult(BaseModel):
    # ... existing fields ...
    per_citation_audits: list[dict] | None = None  # NEW field
    # Each dict: {validated: bool, article_exists: bool, apartado_exists: bool | None,
    #             text_normalized_match: bool, reason: str | None,
    #             citation: {norma, articulo, apartado, language, text}}
```

Why `list[dict]` instead of `list[AuditResult]`: avoids forward-reference + JSON-serialization concerns. AuditResult fields are simple primitives; flat dict round-trips through JSON cleanly. Default `None` for backward-compat with v0.1.20 ARM A/B checkpoints which lack this field.

**Harness change** in `evals/harness.py`: after `auditor.audit()` returns, extract the `AuditedAnswer.audit_results` list, serialize each to flat dict, attach to the constructed `ChatCaseResult`. AuditorAgent already returns this internally; we just propagate.

**Checkpoint change**: `evals/checkpoint.py` writes the new field automatically (Pydantic model_dump_json includes it). Reader handles old format gracefully (Optional default).

**Backward compat**: existing v0.1.20 ARM A/B checkpoints have no `per_citation_audits` field → load as `None`. New v0.1.22 paid run checkpoints will populate it. v0.1.21 T6 diagnostic can be re-run against future checkpoints with full per-citation precision.

### D3 — v1.5 refusal mock end-to-end test

NEW file `tests/unit/agents/test_v1_5_refusal_e2e.py` (~4-5 tests):

- `test_v1_5_refusal_format_passes_capa_a_minItems`: construct mock Sonnet response in v1.5 refusal format (1 Finding with text="<refusal in user language>", citations=[<one valid corpus citation>], severity="high"). Verify Pydantic Answer construction succeeds (Capa B doesn't reject).
- `test_v1_5_refusal_capa_c_does_not_retry`: mock Sonnet returns v1.5 refusal on first attempt; verify analyze() returns immediately (no retry triggered; refusal is valid output).
- `test_v1_5_refusal_auditor_processes_correctly`: take the v1.5 refusal Answer + mock validator returning `validated=True` for the refusal citation → assert Auditor verdict is determined by usual Lenient-Finding + Strict-Answer (likely PASS or RHR depending on severity logic).
- `test_v1_5_refusal_with_invalid_citation_blocks`: take v1.5 refusal Answer with mock validator returning `validated=False` (refusal cites an invented article) → Auditor verdict is BLOCK (Lenient blocks the single Finding → all-blocked → BLOCK). This pins the §6 invariant under refusal: the validator catches a fabricated citation even in refusal text.
- `test_v1_5_refusal_under_strict_mode_round_trip` (optional): the most defensive test — construct Anthropic API-style tool_use response respecting strict mode + minItems:1 + the v1.5 refusal schema → parse + verify round-trips through Answer + Auditor.

All mocks; $0; no API calls.
