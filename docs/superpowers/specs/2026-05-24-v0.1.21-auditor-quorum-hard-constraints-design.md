## 1. Executive summary

v0.1.21 is a **$0 capability milestone** attacking the 77% of v0.1.20's RHR cases that v1.4 prompt did NOT address (per T6.5 root-cause diagnostic):

- **Tier 1 — Auditor RHR aggregation quorum (42% target)**: change `agents/auditor.py` aggregation semantics from "ANY 1 per-citation RHR → turn RHR" to "**≥2 per-citation RHR → turn RHR**". Conservative minimum-change quorum (rejected ⌈K/2⌉+1 majority + 2/3 proportional + severity-weighted alternatives).
- **Tier 2 — Analyst format hard constraints (35% target)**: add three defensive layers preventing `findings=[]` from reaching the Auditor (which v1.4's soft Hard Rule 9 only obtains ~50% compliance from):
  - **Capa A** — Anthropic tool_use `strict: True` + `"minItems": 1` in `findings` schema → API-level guarantee
  - **Capa B** — Pydantic `Field(min_length=1)` on `Answer.findings` → server-side validation catches API-level failures
  - **Capa C** — Aggressive retry (3 attempts max) with specific feedback on validation failure → last-resort recovery

Validation: $0 only in v0.1.21 (unit tests + diagnostic re-run over v0.1.20 ARM A cache simulating new quorum behavior). If diagnostic shows material improvement (> ~10 flips) → v0.1.22 conditional paid A/B 30-case (~€4-6).

The §6 invariant interpretive distinction (carried from ADR-0024/0025/0026) is preserved: production-side citation VALIDATION (`citation/validator.py`) byte-unchanged; v0.1.21 modifies the aggregation layer (Tier 1) and the format/schema layer (Tier 2), both justified via the new ADR-0027.

## 2. Context

### 2.1 Why now — the v0.1.20 T6.5 diagnostic verdict

Per `evals/reports/v0.1.20/rhr-root-cause-diagnostic.md`, the 43 v1.0 RHR cases break down as:

| Bucket | N | % | Status in v1.0 | Status under v1.4 (shipped v0.1.20) |
|---|---:|---:|---|---|
| nonempty-RHR-still-RHR-in-v1.4 | 18 | 42% | Analyst structured citations correctly; Auditor still rejected | UNCHANGED — **Tier 1 target** |
| empty-findings-STILL-empty-in-v1.4 | 15 | 35% | Analyst returned findings=[] | UNCHANGED (v1.4 prompt-only ~50% compliance) — **Tier 2 target** |
| nonempty-RHR-FIXED-by-v1.4 | 6 | 14% | — | Fixed by v1.4 (better citations) |
| empty-findings-FIXED-by-v1.4 | 3 | 7% | — | Fixed by v1.4 (force structure mechanism) |
| other | 1 | 2% | — | Misc |

v0.1.20 attacked the empty-findings path with a soft prompt constraint (Hard Rule 9). That obtained ~50% compliance from Sonnet. The remaining 50% (15 cases of 30 empty-findings cases = 35% of total RHR) need a hard constraint. The 42% nonempty-RHR bucket is structurally NOT addressable via prompt engineering — the Auditor aggregation rejects responses even when the Analyst structures them correctly.

### 2.2 Why Tier 1 is conservative

Three quorum-threshold alternatives were considered (per brainstorming Q1):

- **≥2 per-citation RHR → turn RHR** (CHOSEN): minimum change; one weak citation alone doesn't block the answer; multi-citation responses with one marginal citation now pass. Aligned with H13 evidence (Council frequently disagreed with Auditor on single-marginal-citation cases).
- Majority absolute (⌈K/2⌉+1): too liberal — 2 of 5 invented citations would still pass.
- 2/3 proportional: more code (no real benefit over absolute ≥2).
- Severity-weighted: too sophisticated for initial change (carry to v0.1.23 if needed).

The ≥2 threshold is the conservative minimum that addresses the dominant pattern while keeping §6 spirit: "many failures still block; one isolated failure doesn't".

### 2.3 Why Tier 2 is multi-layer

v1.4's Hard Rule 9 is a **soft constraint at the prompt level**. Per T6.5: Sonnet obtains ~50% compliance. To reach near-100% compliance, multiple defensive layers are needed:

- Capa A (Anthropic strict mode + minItems: 1): API-level guarantee that `findings` is non-empty. Closes the "Sonnet ignored the prompt" path.
- Capa B (Pydantic min_length=1): server-side defense-in-depth. If Anthropic API doesn't enforce strict mode in some response shape, Pydantic catches it.
- Capa C (aggressive retry with feedback): if A+B both fail, retry up to 3 times with feedback specific to the failure (e.g. "your text mentioned articles X, Y but findings was empty — map each claim to a Finding").

This stack mirrors web-form validation defense-in-depth (client-side JS + server-side validation + retry-with-error-feedback).

### 2.4 §6 invariant interpretive distinction (carried from prior ADRs)

| Layer | What it does | v0.1.21 status |
|---|---|---|
| Production-side citation VALIDATION (`citation/validator.py`) | Does the citation exist + literally match the corpus? | **byte-unchanged** |
| Pydantic Answer schema (`citation/schemas.py`) | Format of Analyst output | **Tier 2 Capa B modifies** (min_length=1 on findings) |
| Anthropic tool_use spec (constructed in `agents/analyst.py`) | What Anthropic API enforces | **Tier 2 Capa A modifies** (strict mode + minItems) |
| Analyst retry logic (`agents/analyst.py`) | What happens when output is invalid | **Tier 2 Capa C modifies** (aggressive retry with feedback) |
| Auditor aggregation (`agents/auditor.py`) | Per-citation results → turn verdict | **Tier 1 modifies** (≥2 RHR quorum) |
| Council binding (`agents/council.py`) | Override Auditor on unanimous panel disagreement | byte-unchanged (v0.1.19 state) |
| Analyst prompt files (v1.0-v1.4 .md) | Soft instructions to Sonnet | byte-unchanged |

The "no citation, no answer" guarantee operates entirely on the first layer. v0.1.21 refines aggregation + format layers.

## 3. Architecture / Scope

### D1 — Tier 1: Auditor RHR aggregation quorum (≥2 → turn RHR)

Modify `src/regulaitor/agents/auditor.py` aggregation logic. Currently:

```
if any(per_citation_verdict == RHR for c in citations):
    turn_verdict = RHR
```

Replace with:

```
n_rhr = sum(1 for c in citations if per_citation_verdict == RHR)
if n_rhr >= 2:
    turn_verdict = RHR
```

Edge cases to handle:
- **Single-citation responses (K=1)**: by strict interpretation, K=1 can never reach ≥2, so single-citation responses can't trigger turn-RHR from per-citation aggregation. The other invariants (citation exists + literal match) still apply per-citation; if K=1 fails validator entirely, that's BLOCK not RHR. So this edge case is correct: K=1 with the citation valid → pass; K=1 with citation invalid → block (not RHR).
- **Zero citations (K=0)**: this is the `findings=[]` case. Tier 2 prevents this at format level; if it still reaches the Auditor (e.g. Tier 2 retries exhausted), behavior is unchanged (current code path returns RHR with reason "no findings").
- **BLOCK verdicts**: if any per-citation is BLOCK (e.g. invalid prompt injection detected), the turn is BLOCK regardless of quorum. Tier 1 only changes RHR aggregation, not BLOCK.

Backward-compat / opt-out: NO. Direct semantic change. Rationale: per-citation validation still runs; only aggregation semantics differ. If a future milestone wants the old "ANY RHR → turn RHR" behavior, it's a 1-line revert. No env flag needed (YAGNI).

### D2 — Tier 2 Capa A: Anthropic tool_use strict mode + minItems

Modify `src/regulaitor/agents/analyst.py` tool_use construction:

```python
tools_spec = [
    {
        "name": "emit_answer",
        "description": "Emit the final Answer with findings + citations.",
        "strict": True,  # NEW
        "input_schema": {
            "type": "object",
            "properties": {
                "text": {"type": "string"},
                "findings": {
                    "type": "array",
                    "items": {...},
                    "minItems": 1,  # NEW
                },
            },
            "required": ["text", "findings"],
        },
    }
]
```

Verification needed at T0: confirm Sonnet 4.6 supports `strict: True` on tool_use schemas. If not supported, document gracefully and rely on Capa B+C as the primary enforcement.

Existing `tool_choice` forcing the emit_answer tool stays unchanged.

### D3 — Tier 2 Capa B: Pydantic min_length=1 on Answer.findings

Modify `src/regulaitor/citation/schemas.py`:

```python
# BEFORE:
class Answer(BaseModel):
    text: str
    findings: list[Finding]

# AFTER:
class Answer(BaseModel):
    text: str
    findings: list[Finding] = Field(min_length=1)
```

Behavior on violation: Pydantic raises `ValidationError`. The Analyst's retry mechanism (Capa C) catches this.

Backward-compat: pre-existing tests that construct `Answer(text=..., findings=[])` will fail. Update those tests in T1 or migrate them to `findings=[some_finding]` (single dummy Finding). This is the test-data adaptation cost; not a §6 concern.

### D4 — Tier 2 Capa C: Aggressive retry with specific feedback

Modify `src/regulaitor/agents/analyst.py::analyze`. Currently has 1 retry on `findings`-missing per H8. Extend to:

- Up to 3 attempts total
- On each failure, construct a feedback message specific to the failure mode:
  - If Pydantic `min_length` failure: "Your previous response had `findings=[]`. Your text claimed: '{first 200 chars of text}'. Map each substantive claim to a Finding with citations. If you cannot find a citation in the retrieved context to support a claim, remove that claim from text."
  - If Anthropic API validation failure (Capa A returned an error): translate to a similar specific feedback message.
- After 3 failed attempts, raise `RuntimeError` (the current behavior). Auditor still gets to act on the eventual valid response.

Implementation: the retry loop replaces the current 1-retry block. Test coverage: simulate ValidationError on attempts 1+2, success on attempt 3 → assert correct behavior.

### D5 — Validation: $0 only via diagnostic re-run

NO paid LLM run in v0.1.21. The validation is:

1. **Unit tests** for both tiers (Tier 1: 4-5 tests pinning quorum behavior across K=1, K=2, K=3, K=5 with varying RHR counts; Tier 2: 5-7 tests pinning Capa A schema config + Capa B Pydantic validation + Capa C retry feedback).
2. **$0 diagnostic re-run**: write `scripts/v0121_quorum_diagnostic.py` that loads v0.1.20 ARM A checkpoints (the 18 nonempty-RHR-still-RHR cases) + simulates the new Auditor quorum semantics + counts how many would flip to pass.
3. Emit `evals/reports/v0.1.21/quorum-diagnostic.md` with flip count + per-case detail.

**Decision criterion for v0.1.22 paid validation**:
- Diagnostic shows > 10 cases flip RHR → pass → strong signal, recommend v0.1.22 paid 30-case A/B.
- Diagnostic shows 5-10 cases flip → moderate signal, v0.1.22 optional.
- Diagnostic shows ≤ 5 cases flip → marginal; defer paid validation indefinitely or accept that Tier 1's value is mostly Tier 2-mediated (cleaner format → fewer false RHRs from format issues).

Tier 2 has no equivalent $0 diagnostic (the question "how often does v1.4 obtain Sonnet compliance" was answered by v0.1.20 T6.5 = ~50%); the value of Tier 2 is the deterministic guarantee, not a measurable rate improvement. Unit tests + the diagnostic-flip-count for Tier 1 are the v0.1.21 evidence base.

### D6 — Single ADR-0027 covering both tiers

Single ADR is more cohesive than splitting into two. Both tiers attack the same observed problem (false RHR in v0.1.20 baseline) at different layers. Single ADR documents:

- Context: T6.5 diagnostic + the 77% target
- D1 quorum decision + 3 rejected alternatives (majority / proportional / severity-weighted)
- D2-D4 hard constraints + 2 rejected alternatives (only A+B without retry; A+B+C+D with format-extract fallback)
- D5 validation strategy + alternative (paid A/B in v0.1.21 vs deferred to v0.1.22)
- Consequences: positive + §22.22 negative
- References: T6.5 diagnostic + companion ADRs

Mirror ADR-0025 (5-decision Council binding) and ADR-0026 (6-decision paid validation) precedents.

## 7. Risks + mitigations

| Risk | Mitigation |
|---|---|
| Anthropic strict mode not supported on Sonnet 4.6 | T0 verification step; if unsupported, document gracefully and rely on Capa B+C |
| Tier 1 quorum is too aggressive (≥2 lets through real errors) | Conservative ≥2 (not majority); unit tests pin K=1/2/3/5 edge cases; T6 diagnostic counts what would flip; if data later shows safety regression in paid validation, easy 1-line revert |
| Tier 2 Pydantic change breaks pre-existing tests | T1 inventories which tests construct `Answer(findings=[])` and updates them in T3 |
| Capa C aggressive retry triples cost in pathological cases | Hard cap at 3 attempts; if all 3 fail, RuntimeError surfaces (current behavior); not a $0 milestone risk (no paid runs) but documented for v0.1.22 |
| §6 critic claims aggregation change weakens the invariant | ADR-0027 §6 interpretive distinction section (carried from ADR-0024/0025/0026); per-citation validation unchanged; only aggregation refined |
| Unit tests miss edge cases that paid validation would catch | v0.1.22 conditional paid A/B is the rigorous validation; v0.1.21 ships capability with $0 evidence |
| Diagnostic re-run gives misleading signal (cache mining ≠ real run) | Diagnostic methodology documented; flip count is a LOWER bound (assumes same Analyst output; real run might produce different outputs entirely); v0.1.22 paid validation if triggered measures the real effect |
| Closure ceremony catches a HARD invariant fire late | T-final 7 invariant checks before squash; if any fires, revert + diagnose |
| ADR-0027 documents two tiers as one — reader confusion | Mirror ADR-0025/0026 multi-decision structure (D1-D6 with clear labels); both tiers attack same problem so cohesion > separation |
